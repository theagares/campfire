벤치마크 데이터 — 무엇을 받고 무엇을 만들 것인가

회사 기밀 온톨로지 · 2026-09-07 · 설계 계획서의 후속

v2 계획서가 §0·§2 의 결론을 뒤집었다

“기밀 탐지에 공개 데이터가 없다”는 온톨로지를 회사마다 채운다는 v1 전제에서만 참이다. 온톨로지를 고정하면 회사 데이터 + 정답 KG 소스(OpenDART·REFinD·CUAD)가 있다 — v2 §4. 이 문서에서 살아남는 것: KDPII(PII 재현율), KLUE-NER(경계 채점), 주입 벤치마크(R6 전용), 라이선스 표.

찾아보니 벤치마크는 하나가 아니라 네 개의 서로 다른 질문이었다. 그중 정작 제일 중요한 “회사 기밀을 잡는가”는 공개 데이터가 원리적으로 존재할 수 없다. 받을 것과 만들 것을 나눈다.

지금 받는다 — 2개

KDPII · 한국어 PII, CC BY 4.0

KLUE-NER · 한국어 경계, HF 한 줄

직접 만든다 — 1개

DART 공시 + 합성 온톨로지 주입

기밀 탐지는 이 방법밖에 없다

나중에

KLUE-RE · TAB · ACTER · 모두의 말뭉치

필요해지는 시점이 각각 다르다

0벤치마크가 네 개인 이유

“기밀 탐지 벤치마크”를 하나 구하려 했는데, 우리 파이프라인이 답해야 할 질문이 서로 다른 층에 있다.

#질문공개 데이터
1등록된 기밀 용어를 잡는가 — 온톨로지 매처의 재현율·정밀도없다 만들어야 함
2한국어 경계에서 안 깨지는가 — 조사·중첩·표기 흔들림KLUE-NER
3기존 PII 탐지가 실제로 몇 %인가 — #143 이 드러낸 구멍KDPII
4후보 추출·관계 제안이 쓸 만한가 — 3~4단계대체재만

1번에 공개 데이터가 없는 건 데이터가 부족해서가 아니다

“오로라가 기밀인가”의 정답은 그 회사 안에만 있다(설계서 §1). 어떤 공개 코퍼스도 우리 온톨로지의 정답을 담을 수 없다 — 담는 순간 그건 이미 기밀이 아니다.

DLP 문헌도 같은 지점에서 막힌다. 기존 DLP 평가셋은 문서를 “민감/비민감”(또는 몇 단계)으로 문서 단위로 태깅해서, 어느 구간을 가려야 하는가를 재는 데는 쓸 수 없다고 TAB 논문이 직접 지적한다. 우리가 필요한 건 정확히 그 구간 단위 정답이다.

1지금 받을 것 — 두 개면 충분하다

① KDPII — 한국어 PII 구간 정답 CC BY 4.0

항목값
정식명Korean Dialogic Dataset for PII De-identification
배포Zenodo 10.5281/zenodo.10968609 — 로그인·신청 없음
크기·형식62.2MB JSON (train 49.8 / test 6.1 / valid 6.3)
라이선스CC BY 4.0 — 출처 표기하면 상업적 이용 가능
한계대화체다. 우리 입력은 문서라 장르가 다르다

이걸 첫 번째로 고른 이유는 지금 이미 알려진 구멍이 있기 때문이다. #143 에서 주소가 마스킹 없이 나갔고, 그때 남긴 미해결 항목이 “지원 PII 10종 중 주소 하나가 새는 걸 우연히 발견했는데 나머지 9종은 아무도 모른다” 였다. KDPII 는 그 “아무도 모른다”를 숫자로 바꿔주는 유일한 무료 한국어 구간 단위 데이터다.

참고로 논문이 보고한 자체 베이스라인은 대화 데이터 F1 0.66, 행정·양식형 평가셋 F1 0.79 다. 우리 인코더 모델이 이 근처면 정상, 한참 아래면 문제다 — 절대 기준이 없던 자리에 기준선이 생긴다.

확인하고 받을 것

인스턴스 수가 출처마다 다르게 보였다 — 논문 쪽은 대화 4,891건 / 행정형 540건, 다른 설명에는 53,778건이 나온다. 같은 걸 다르게 센 것인지 별개 수치인지는 받아서 직접 세는 게 빠르다. 라벨 종류(주소 포함 여부)도 같이 확인해야 한다 — 그게 이 데이터를 고른 이유 자체이므로.

② KLUE-NER — 한국어 경계 문제 CC BY-SA 4.0

from datasets import load_dataset
ner = load_dataset("klue/klue", "ner")   # train 10k / validation 2k

설계서 §5 에서 “한국어에서 실제로 어려운 지점”으로 조사 경계를 꼽았는데, KLUE-NER 이 정확히 그 문제를 정면으로 다루는 데이터다. 문자 단위 태깅을 채택한 이유를 “한국어 형태소 특성을 반영하기 위해”라고 밝히고, 형태소·문맥 단서를 둘 다 써야 풀리게 개체 유형을 달아놨다.

우리가 여기서 재는 건 개체명 인식 성능이 아니라 우리 매처의 우측 경계 휴리스틱이다. “오로라의”는 잡고 “오로라기”는 버리는 규칙이 실제 한국어에서 몇 % 맞는지. 정답 경계가 문자 단위로 달려 있으니 그대로 채점된다. 뉴스와 웹 텍스트를 모두 포함해서 문체 편향도 덜하다.

왜 둘 뿐인가

지금 답이 필요한 질문은 “기존 탐지가 몇 %인가”와 “매처가 한국어에서 깨지나” 둘이다. 나머지 데이터는 아직 존재하지 않는 단계를 위한 것이다. 3단계 후보추출을 만들기 전에 ACTER 를 받아두면 그냥 디스크만 먹는다.

2직접 만들 것 — 기밀 탐지 벤치마크

1번 질문에는 살 수 있는 데이터가 없으니 구성으로 정답을 만든다. 가상 회사의 온톨로지를 정하고, 실제 한국어 기업 문서에 주입한다. 주입한 위치가 곧 정답이라 라벨링 비용이 0이다.

배경 문서는 DART 공시

기준DART dart.fss.or.kr
기밀 문제없다 — 법정 공시라 애초에 공개 문서다
문체실제 한국 기업 문서. 사업보고서·감사보고서의 그 말투
포맷우리가 실제로 파싱할 형식(PDF 등)으로 바로 온다
비용·양무료, 사실상 무제한

대안으로 정부 보도자료(공공누리)도 되지만, 기업 문서 문체가 아니다. 우리 탐지 대상은 사내 문서이고 DART 가 공개 자료 중 거기에 가장 가깝다.

주입 설계 — 세 종류의 문서가 필요하다

A. 양성 가상 온톨로지 용어를 심은 문서 → 재현율을 잰다 B. 함정 같은 단어를 일반 의미로 쓰는 문서 → 정밀도를 잰다 C. 음성 손대지 않은 원본 공시 → 오탐률을 잰다

B 가 이 벤치마크의 핵심이다. A 와 C 만 있으면 “모든 걸 다 잡는다”는 탐지기가 만점을 받는다. 설계서에서 solo 축을 1급 필드로 둔 이유가 오탐 폭발을 막는 것이었는데, 그 장치가 작동하는지는 함정 문서에서만 드러난다.

클래스양성(A)함정(B)
PROJECT_CODENAME“오로라 프로젝트 2차 단가표”“오로라 관측 투어 상품”
FINANCIAL_METRIC“오로라 납품단가 12,400원”“업계 평균 단가가 상승했다”
CLIENT코드명과 같은 문단에 등장단독 언급(공개 거래처 소개)

그리고 중첩(설계서 §5)을 반드시 넣는다 — 오로라 / 오로라 프로젝트 / 오로라 프로젝트 2차 단가표 를 같은 문서에 두고, 매처가 가장 긴 것을 잡는지 본다. 가장 위험한 형태를 놓치는 실패가 여기서만 보인다.

규모는 작아도 된다

문서 30~50건이면 첫 신호로 충분하다. 정답이 구성으로 나오니 늘리는 건 스크립트 문제이고, 지금 필요한 건 큰 숫자가 아니라 “함정에서 안 터지는가”라는 예/아니오다.

3나중에 — 필요해지는 시점이 다 다르다

데이터언제라이선스·비고

모두의 말뭉치 신문 배경 코퍼스가 필요해질 때 신청·인증 필요. 설계서 background_corpus 자리

TAB 은 데이터가 아니라 방법을 가져온다

영어 판례라 우리 입력과 안 맞지만, 주는 것이 두 가지 있다.

  • 직접 식별자 vs 준식별자(quasi-identifier) 구분 — 설계서 §2-① 의 solo 축이 바로 이 구분이다. 남이 만든 어노테이션 스키마를 베낄 수 있다
  • 프라이버시 보호와 유용성 보존을 함께 재는 지표 — 우리 문제로 옮기면 “기밀을 가렸는가”와 “가리고도 질문이 통하는가”다. 마스킹 게이트웨이는 둘 다 필요하다

덧붙여 KDPII 자체가 TAB 을 참고해 라벨 체계를 만들었다고 밝히고 있어, 둘을 같이 보면 정합이 맞는다.

4라이선스 — 하나만 조심하면 된다

AI Hub 는 쓰지 않는다

한국어 데이터를 찾으면 AI Hub 가 제일 먼저 나오지만, 이용정책이 비상업 연구개발 목적 한정이고 제공자 승인 없이 제3자 제공 금지다. 해커톤 시연은 되겠지만 제품에 들어가는 순간 위반이고, 데이터를 뺀 채로 “이걸로 검증했다”고 말하기도 애매해진다. 처음부터 안 쓰는 쪽이 싸다.

KLUE 의 ShareAlike 는 평가에만 쓰면 문제가 없다 — 데이터를 재배포하거나 그것으로 만든 파생 데이터셋을 배포할 때 전이된다. 점수만 뽑는 용도라 걸리지 않는다.

5첫 액션

  1. KDPII 받아서 라벨 종류부터 센다 — 주소가 라벨에 있는지, 인스턴스 수가 실제로 몇인지. 이 데이터를 고른 이유가 그것이므로 여기서 확인이 안 되면 다른 걸 찾아야 한다
  2. KLUE-NER 로 경계 휴리스틱을 채점한다 — 매처를 만들기 전에 할 수 있다. 정답 경계만 있으면 “매치 뒤 한 글자가 조사인가” 규칙의 정확도는 바로 나온다
  3. DART 문서 30~50건으로 A/B/C 세트를 만든다 — 가상 온톨로지는 설계서의 오로라·삼성전자·납품단가 예시를 그대로 쓰면 된다

순서에 이유가 있다

1·2번은 온톨로지 코드를 한 줄도 쓰기 전에 끝난다. 그리고 1번 결과가 나쁘면 계획이 바뀐다 — PII 재현율이 생각보다 낮으면 기밀 온톨로지보다 그게 먼저다. 기밀을 잡아도 이름·주소가 새면 게이트웨이가 아니다.

확인한 것: Zenodo 레코드(크기·라이선스·형식), HuggingFace klue/klue 서브셋·라이선스·분할, TAB 초록(출처·규모·라이선스), AI Hub 이용정책, DART 공개 여부.
확인하지 않은 것: 실제 다운로드는 하지 않았다 — 라벨 종류와 인스턴스 수는 받아서 세야 한다.
