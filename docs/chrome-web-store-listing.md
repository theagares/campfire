# Chrome 웹스토어 등록 절차 · 제출 문안

확장 코드는 이미 심사 통과 가능한 상태다(MV3, 원격 코드 0건, 모든 통신이 `127.0.0.1`).
남은 건 계정·서류·자산이다. 이 문서는 대시보드에 그대로 붙여 넣을 문안을 담는다.

## 0. 먼저 확인된 사실 (다시 조사할 필요 없음)

- 확장 ID는 스토어 발행 시 새로 발급되어 개발자 모드로 로드했던 ID와 달라진다.
  **엔진 CORS는 `engine/app/main.py`의 `^chrome-extension://[a-p]{32}$` 정규식이라
  어떤 ID든 통과한다** — manifest에 `"key"`를 넣어 ID를 고정할 필요가 없다.
- `tabs` 권한은 제거했다(`tabs.create`/`sendMessage`만 쓰고 `tabs.query`·`tab.url`은
  쓰지 않아 불필요했다). 설치 시 "브라우징 기록 읽기" 경고가 뜨지 않는다.
- 배포 설치본에는 Upstage API 키가 없다(`.env`는 gitignore이고 패키징 경로 밖). 따라서
  기본 상태에서 외부로 나가는 사용자 데이터가 없다 — 데이터 신고서를 이 기준으로 쓴다.

## 1. 개발자 계정 (최초 1회)

1. https://chrome.google.com/webstore/devconsole 접속 (2단계 인증 켜진 구글 계정 필요)
2. 등록 수수료 **$5** 결제 — 계정당 1회
3. 계정 설정에서 **연락처 이메일 인증**, EU **DSA 거래자/비거래자 신고** 완료
   (비거래자로 신고하면 EU 노출이 제한될 수 있다 — 무료 배포면 보통 비거래자)

## 2. 패키지

`release.yml`이 릴리스마다 `campfire-extension-<version>.zip`을 만들어 GitHub 릴리스에
붙인다(`manifest.json`이 zip 루트, `tests/` 제외 — CI에서 두 조건을 실제로 열어 확인한다).
그 zip을 그대로 업로드하면 된다.

로컬에서 직접 만들려면:

```bash
cd extension && zip -r ../campfire-extension.zip . -x 'tests/*'
```

`extension/` 폴더째 압축하면 안 된다 — `manifest.json`이 zip 루트에 있어야 한다.

## 4. 그래픽 자산

| 항목 | 규격 | 상태 |
|---|---|---|
| 아이콘 | 128×128 PNG | 있음 (`extension/icons/icon128.png`) |
| 스크린샷 | **1280×800** 또는 640×400 PNG/JPEG, 최소 1장(최대 5장) | **새로 찍어야 함** — `screenshot/`의 기존 파일은 규격 불일치 |
| 작은 프로모 타일 | 440×280 | 대시보드에서 현재 필수인지 확인 후 준비 |

스크린샷으로 쓸 장면(이 순서가 제품을 가장 잘 설명한다):
1. 사이드패널이 PII를 가린 결과를 보여주고 전송/취소를 묻는 화면
2. 인젝션이 탐지돼 차단된 화면
3. 팝업(엔진 연결됨 상태)

## 5. 권한 사유 (심사 양식에 항목별로 입력)

- **activeTab / scripting**: 사용자가 전송을 시도한 탭에서 프롬프트·첨부 내용을 가로채
  검사하고, 마스킹된 결과를 다시 입력창에 넣기 위해 필요합니다.
- **sidePanel**: 무엇이 탐지·마스킹됐는지 보여주고 사용자가 전송 여부를 직접 결정
  (human-in-the-loop)하게 하는 UI입니다.
- **storage**: 보호 on/off 설정과 로컬 엔진 주소·포트 캐시를 저장합니다.
- **host `http://127.0.0.1/*`, `http://localhost/*`**: 검사를 수행하는 로컬 엔진(사용자 PC의
  Campfire 앱)에 요청하기 위해 필요합니다. 외부 서버가 아닙니다.
- **host (chatgpt.com, claude.ai, gemini.google.com, copilot.microsoft.com, grok.com,
  perplexity.ai)**: 전송 전 검사를 걸 대상 AI 서비스입니다. 이 목록 외 사이트에서는
  동작하지 않습니다.
- **원격 코드 미사용**: 모든 코드가 패키지에 포함되어 있습니다(`eval`·외부 스크립트 로딩 없음).

## 6. 데이터 사용 신고 (Privacy 탭)

수집/사용한다고 체크할 항목:

- **웹사이트 콘텐츠** — 사용자가 전송하려는 프롬프트 본문과 첨부 파일 내용
- **개인 통신** — 위 내용이 AI 서비스와의 대화에 해당할 수 있음
- **개인 식별 정보** — 이 확장의 목적 자체가 입력 안의 이름·연락처·주민번호를 찾는 것이다
- **인증 정보** — 입력 안의 API 키·토큰도 탐지 대상이다(release.yml 이 실제로 GitHub
  토큰 마스킹을 검증한다)

셋째·넷째 항목을 빼면 "실제 처리하는 것보다 적게 신고"가 되어 반려 사유가 된다.
더 넓게 신고해도 불이익은 없다 — 어차피 전송 대상이 로컬뿐이라 아래 인증 3개를
그대로 체크할 수 있다.

세 가지 인증(certification) 모두 체크 가능하다:

- 승인된 용도 외로 사용하지 않음 ✅
- 제3자에게 판매·양도하지 않음 ✅ (전송 대상이 `127.0.0.1`뿐)
- 신용도 평가·대출 목적으로 쓰지 않음 ✅

설명란에 넣을 문장:

> 입력 내용은 사용자 PC 내부의 로컬 엔진(127.0.0.1)으로만 전송되어 PII·프롬프트 인젝션
> 탐지에 사용되며, 개발자 서버나 제3자로 전송되지 않습니다. 원격 서버 없음, 분석·광고
> SDK 없음. 로컬 검사 이력은 원문 없이 메타데이터(탐지 건수·유형·위치)만 저장됩니다.

## 7. 공개 범위 — 처음에는 **Unlisted(비공개 링크)** 권장

- 심사는 공개와 동일하게 받지만 스토어 검색에 노출되지 않고, 링크를 아는 사람만 설치한다
- 데모·해커톤·초기 사용자 배포에 적합하고, 준비되면 Public으로 바꾸면 된다
- 더 좁히려면 Private(테스터 지정) — 다만 링크 공유가 안 된다

## 8. 심사

제출 후 보통 수 시간~며칠. 첫 제출이고 host_permissions가 넓으면 1주까지 갈 수 있다.
반려되면 보통 사유가 구체적으로 온다(대개 개인정보처리방침·데이터 신고 불일치).

심사자가 **앱 없이 확장만** 열어볼 수 있다는 점을 염두에 둘 것 — 팝업에서 "미연결"일 때
앱 다운로드 링크가 보이도록 해뒀고, 상세 설명 첫 줄에도 앱 필요를 명시했다.

## 9. 나중에 (지금 할 필요 없음)
