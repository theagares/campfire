# 아이콘 마스터 (손으로 그리는 원본)

여기 있는 파일에서 앱·트레이·확장 아이콘이 **전부 자동 생성**된다.

```bash
cd desktop && node scripts/gen-icons.js
```

생성물(`build/icon.png`, `assets/icon.ico`, `extension/icons/*` 등)은 직접 수정하지 말 것 —
다음 실행 때 덮어써진다. 고칠 게 있으면 여기 마스터를 고치고 다시 돌린다.

> **주의 — 현재 커밋된 트레이·확장 아이콘은 스크립트 생성물이 아니다.**
> 16·32px 처럼 작은 크기는 디자이너가 픽셀 단위로 손봐 내보낸 파일이 들어가 있어,
> 스크립트를 돌리면 그게 자동 축소본으로 덮인다. 아이콘이 목적이 아니라면 실행 후
> `git status` 를 보고 의도하지 않은 파일은 `git checkout --` 로 되돌릴 것.

## 그려야 하는 것 3개

### `app-icon.png` — 앱 아이콘
- **1024×1024 이상**, 정사각, PNG-32(알파 포함)
- **실제 아트는 캔버스의 약 80%(1024 기준 824px)만** 차지하고 나머지는 투명 여백.
  macOS 는 이 여백을 전제로 레이아웃하므로, 꽉 채우면 Dock 에서 혼자 커 보인다.
- **모서리 둥근 처리를 그림에 직접 포함**해야 한다. OS 가 자동으로 안 깎아준다.
- 16px 까지 축소되니 얇은 선·작은 글자는 뭉갠다. 형태를 단순하게.

> 앱 아이콘은 **애니메이션이 불가능**하다 — macOS Dock 도 Windows 작업표시줄도
> 정지 이미지만 받는다. 움직이는 표현은 아래 트레이에서만 가능하다.

### `tray-mac.png` — macOS 메뉴바 아이콘
- **88×88 이상**, 정사각
- **단색 검정(#000) + 투명 배경.** macOS 템플릿 이미지는 **알파만 읽고 RGB 는 버린다** —
  색을 넣어도 화면에 반영되지 않고, 다크/라이트 모드에 맞춰 OS 가 알아서 반전한다.
- 배경을 불투명하게 두면 메뉴바가 **통짜 사각형으로 칠해진다**(과거 실제 발생한 버그).
  스크립트가 이 두 가지를 검사해 경고한다.
- 22px 로 표시된다. 디테일을 최대한 덜어낼 것.

### `tray-win.png` — Windows 작업표시줄 아이콘
- **64×64 이상**, 정사각
- **흰색 또는 컬러.** Windows 는 템플릿 반전을 해주지 않아서, 검정으로 그리면
  Windows 11 기본 다크 작업표시줄에서 거의 보이지 않는다.
- 16px 로 표시된다.

### `ui-hero.png` — 앱 홈 화면 / 확장 사이드바 일러스트 (선택)
- **224×224 이상**, 정사각, PNG-32
- 아이콘이 아니라 **화면 안에 크게 들어가는 그림**이다(홈 104px, 사이드바 72px).
  16px 까지 줄어들 일이 없으니 디테일이 있어도 된다 — 아이콘 마크처럼 단순화할 필요 없다.
- 여백은 넣지 않는다. 표시 영역을 꽉 채우는 게 맞다(앱 아이콘의 80% 규칙은 Dock 전용).
- 이 파일이 없으면 아이콘 마크에서 대신 뽑는다(예전 동작).

## 트레이 애니메이션 (선택)

트레이는 프레임을 갈아끼워 애니메이션할 수 있다. 파일 대신 **같은 이름의 폴더**에
프레임을 넣으면 된다:

```
tray-mac/frame-01.png
tray-mac/frame-02.png
tray-mac/frame-03.png
tray-win/frame-01.png   ← Windows 도 따로 만들 수 있다
```

- 파일명 **정렬 순서대로** 재생된다. `01`, `02` 처럼 자리수를 맞출 것.
- 모든 프레임이 같은 크기·정사각이어야 한다.
- 정지 상태(검사 중이 아닐 때)로 쓸 대표 이미지는 **1번 프레임**이다.
- 파일(`tray-mac.png`)과 폴더(`tray-mac/`)가 둘 다 있으면 폴더를 쓴다.

생성 결과는 `assets/tray-frames/` 에 들어가고, 프레임 목록과 재생 간격은
`assets/tray-frames/manifest.json` 에 기록된다.

> 프레임을 만들어도 **재생 코드는 아직 없다.** `main/tray.js` 는 현재 정지 아이콘만
> 쓴다. 실제로 움직이게 하려면 manifest 를 읽어 `tray.setImage()` 를 돌리는 작업이
> 따로 필요하다.

## 생성되는 파일

| 출력 | 크기 | 용도 |
|---|---|---|
| `desktop/build/icon.png` | 1024 | electron-builder 원본 → dmg/exe 아이콘 |
| `desktop/assets/icon.png` | 256 | 창 아이콘 (mac/linux) |
| `desktop/assets/icon.ico` | 16·24·32·48·64·128·256 | 창/작업표시줄 아이콘 (Windows) |
| `desktop/assets/tray-icon.png` `@2x` | 22 · 44 | macOS 메뉴바 |
| `desktop/assets/tray-icon-win.png` `@2x` | 16 · 32 | Windows 작업표시줄 |
| `extension/icons/icon{16,32,48,128}.png` | 16·32·48·128 | 확장 프로그램 |
| `desktop/assets/figma/home-hero.png` | 224 | 앱 홈 화면 (표시 104×107) |
| `extension/sidepanel/assets/agent-shield.png` | 144 | 확장 사이드바 (표시 72) |
| `desktop/assets/tray-frames/*` | 위와 동일 | 애니메이션 프레임(폴더를 준 경우) |

## 내보내기 시 주의

- **PNG-32(RGBA 8bit)** 로 내보낼 것. 인터레이스(Adam7)는 지원하지 않는다.
- JPG 는 투명도가 없어 쓸 수 없다.
- 축소는 area-average 로 선형 광량 + 프리멀티플라이 상태에서 계산하므로, 마스터가
  충분히 크면 작은 크기에서도 가장자리가 깨끗하게 나온다. 미리 작게 만들어 넣지 말 것.
